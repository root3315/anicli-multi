# anicli-multi — мультиисточниковый поиск аниме

**Дата:** 2026-08-13
**Статус:** согласован, готов к планированию реализации

## 1. Проблема

`anicli-ru` ищет строго в одном источнике, выбранном при запуске (`-s animego`). На практике
конкретного тайтла на конкретном источнике может не быть, и пользователь вынужден выходить из
REPL и перезапускать с другим `-s`. Плюс каждый поиск требует набирать слово `search`.

## 2. Цель

Инструмент `ani`, который:

1. Ищет сразу по нескольким источникам параллельно.
2. Показывает **одну строку на тайтл** с пометкой, на каких источниках он есть — без дублей.
3. Принимает голый текст как поисковый запрос, без слова `search`.
4. Ставится одной командой на Windows, Linux и macOS.

## 3. Не-цели

- Не переписываем воспроизведение, выбор серий, озвучек, историю просмотров — переиспользуем
  `anicli-ru`.
- Не делаем свой парсер сайтов — это работа `anicli-api`.
- Не мержим озвучки разных источников в один список внутри одной серии. Источник выбирается
  один раз, до перехода к сериям.
- Не публикуем в apt/npm (обоснование в §10).

## 4. Пользовательский опыт

```
$ ani
~ наруто

  #  Название                          Источники
  1  Наруто: Ураганные хроники         animego, hdrezka, anilibria
  2  Боруто: Новое поколение Наруто    animego, hdrezka
  3  Наруто: Последний фильм           hdrezka
  ⚠ yummy-anime: timeout

~/multi 1

  #  Источник
  1  animego
  2  hdrezka
  3  anilibria

~/multi/source 2
  [таблица серий — штатный экран anicli]
```

Если тайтл найден на одном источнике, шаг выбора источника пропускается.

**Команды REPL:** голый текст = поиск. Плюс алиасы `s` (search), `o` (ongoing), `h` (history),
`q` (exit). Штатные команды `search`, `ongoing`, `history`, `config`, `help`, `exit` работают
как раньше.

**Запуск:** `ani` — сразу REPL. `ani наруто` — сразу с поиском. `ani --sources animego,hdrezka`
— разовое переопределение набора источников.

## 5. Архитектура

Отдельный дистрибутив `anicli-multi`, зависящий от `anicli-ru>=6.1,<7`. Код `anicli-ru` не
модифицируется — расширяем его штатными механизмами.

```
anicli_multi/
  normalize.py   — нормализация названий для группировки
  aggregate.py   — параллельный поиск по источникам, группировка, отчёт об ошибках
  fsm.py         — MultiSearchFSM: свой первый шаг, остальное наследуется
  commands.py    — регистрация команд поверх APP, алиасы, голый текст = поиск
  compat.py      — проверка совместимости с установленной версией anicli-ru
  config.py      — чтение/запись пользовательского конфига
  cli.py         — точка входа (typer), console_script `ani`
```

### Точки интеграции с anicli-ru

| Что используем | Вид | Риск |
|---|---|---|
| `@command` из `anicli.cli.ptk_lib` | публичный декоратор | низкий |
| `@fsm_route` / `@fsm_state`, `BaseAnimeFSM` | публичное наследование | низкий |
| `APP.command_manager.get_command()` / `.execute()` | публичные методы | низкий |
| `APP.start_fsm(route, state, context)` | публичный метод | низкий |
| Ключи контекста FSM (`results`, `anime`, `episodes`, `extractor_name`, …) | внутренний контракт | **средний** |
| `dynamic_load_extractor_module` из `anicli.common.extractors` | внутренний, но стабильный | низкий |

Единственная существенная связанность — набор ключей контекста FSM. Её закрывает `compat.py`
(см. §9).

### MultiSearchFSM

Наследуется от `BaseAnimeFSM`, который уже содержит `step_2` (выбор серии), `step_3`
(выбор озвучки и запуск mpv) и `step_3_batched` (пакетное воспроизведение). Переопределяются
только первые шаги:

- **`step_1`** — пользователь выбрал строку-группу. Если в группе один источник, сразу
  проставляем `ctx["extractor_name"]`, `ctx["results"] = [результат]`, `ctx["result_num"] = 0`,
  грузим аниме и серии, переходим в `step_2`. Если источников несколько — рендерим таблицу
  источников и переходим в `step_1_source`.
- **`step_1_source`** — пользователь выбрал источник. Дальше та же логика, что выше.

Критично: `extractor_name` проставляется **после** выбора источника, поэтому история просмотров
записывается с корректным источником и корректно переигрывается.

## 6. Группировка

Ключ группировки — нормализованное название:

1. Приведение к нижнему регистру.
2. `ё` → `е`.
3. Удаление технических хвостов: `[1-220 из 220]`, `(ТВ-2)`, `/ Naruto Shippuuden` и подобных
   альтернативных названий после разделителя `/`.
4. Удаление пунктуации, схлопывание пробелов.

**Склейка только по точному совпадению нормализованного ключа.** Fuzzy-матчинг сознательно не
применяется: он превращает «Наруто» и «Наруто: Ураганные хроники» в одну строку, а это хуже,
чем лишняя строка в списке. Русское и ромадзи-название одного тайтла на разных источниках в одну
строку не схлопнутся — это принятое ограничение.

Отображаемое название группы — вариант от источника с наивысшим приоритетом.

Порядок групп: по числу источников (убывание), затем по приоритету лучшего источника, затем по
названию. Тайтлы, доступные на нескольких источниках, оказываются наверху.

## 8. Конфиг

Файл в платформенной директории конфигов (`platformdirs`): `%APPDATA%\anicli-multi\config.json`
на Windows, `~/.config/anicli-multi/config.json` на Linux. Поля: `sources`, `quality`,
`mpv_opts`, `timeout`, `bare_text_search`. Отсутствие файла — не ошибка, применяются дефолты.

Формат JSON, а не TOML, сознательно: `tomllib` появился только в Python 3.11, а мы поддерживаем
3.9+. TOML потребовал бы `tomli` для чтения и `tomli-w` для записи — две зависимости ради пяти
полей. JSON читается и пишется стандартной библиотекой на всех поддерживаемых версиях.

## 9. Ошибки и устойчивость

- Источник упал или таймаутнул → он исключается из выдачи, под таблицей строка
  `⚠ <источник>: <причина>`. Остальные результаты показываются.
- Все источники упали → «ничего не найдено», REPL продолжает работать.
- Голый текст, совпавший с опечаткой в команде (`sarch наруто`), уйдёт в поиск. Принятое
  поведение; отключается настройкой `bare_text_search = false`.
- **Проверка совместимости при старте** (`compat.py`): убеждаемся, что установленная версия
  `anicli-ru` предоставляет ожидаемые атрибуты и ключи контекста. Расхождение → внятное
  сообщение с указанием версий вместо трейсбэка.

## 10. Упаковка и распространение

**PyPI.** Установка одинакова на всех платформах:

```
pipx install anicli-multi      # или: uv tool install anicli-multi
```

Почему не apt и не npm:

- **npm** — реестр экосистемы Node. Python-приложение там жило бы обёрткой, которая всё равно
  требует установленный Python. Антипаттерн.
- **apt** — нужен Debian-пакет и собственный репозиторий либо прохождение в Debian/Ubuntu.
  Долго, привязано к версиям дистрибутива, и Python пользователю всё равно нужен.

Обе задачи, ради которых обычно смотрят на apt/npm, решаются иначе: standalone-бинари
(PyInstaller) в GitHub Releases для машин без Python, и, при желании, PKGBUILD для AUR. Это
пост-релизная работа, в первую версию не входит.

Метаданные: `pyproject.toml`, hatchling, `requires-python = ">=3.9"` (как у upstream), лицензия
MIT, атрибуция `anicli-ru` и `anicli-api` (обе MIT) в README и NOTICE.

Entry points: `ani` и `anicli-multi` — обе на `anicli_multi.cli:main`.

**Публикация — только по явной команде владельца.** Реализация доводится до состояния
«готово к публикации», сама публикация не выполняется автоматически.

## 11. Тесты

- **Юнит, без сети** — нормализация и группировка. Основной риск проекта («каша из повторок»)
  живёт здесь, поэтому покрытие максимальное: реальные названия из выдачи всех источников,
  краевые случаи, проверка что разные тайтлы НЕ склеиваются.
- **Юнит, без сети** — агрегатор на моках: таймаут одного источника, падение источника,
  пустая выдача, все источники упали.
- **Юнит** — резолв группы в источник и корректность `extractor_name`.
- **Интеграционный, с сетью** — реальный поиск, помечен `@pytest.mark.network`, из основного
  прогона исключён.
- **Smoke совместимости** — `compat.py` против фактически установленного `anicli-ru`. Именно
  этот тест ловит поломку после обновления upstream.

CI (GitHub Actions): ruff, mypy, pytest на Windows и Linux, Python 3.9–3.13.

## 12. Риски

| Риск | Митигация |
|---|---|
| Обновление `anicli-ru` ломает контракт FSM | Пин `<7`, `compat.py`, smoke-тест в CI |
| Источник меняет вёрстку и отваливается | Это зона ответственности `anicli-api`; у нас деградация мягкая — источник просто выпадает из выдачи |
| Поиск идёт по самому медленному источнику | Индивидуальный таймаут на источник (дефолт 10 с) ограничивает общее время поиска сверху: выдача рендерится один раз, когда все источники либо ответили, либо истекли |
| Одинаковый тайтл под разными названиями не склеился | Принятое ограничение, задокументировано в README |
