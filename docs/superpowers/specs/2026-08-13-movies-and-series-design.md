# Фильмы и сериалы в anicli-multi

**Дата:** 2026-08-13
**Статус:** согласован, готов к планированию реализации
**Предшествующая спека:** [2026-08-13-anicli-multi-design.md](2026-08-13-anicli-multi-design.md)

## 1. Проблема

`anicli-multi` находит только аниме. Источник `hdrezka` — общий каталог с фильмами,
сериалами, мультфильмами и шоу, но `anicli-api` отбрасывает всё, кроме аниме.

Механика отбрасывания (`anicli_api/source/parsers/hdrezka_parser.py:208`):

```python
v2 = [i for i in v1 if "data-url" in i.attrib and "/animation/" in i.get("data-url", "")]
```

**Сам HTTP-запрос не фильтрован** — он идёт по всему каталогу сайта. Фильмы и сериалы
приходят в ответе и выбрасываются на этапе разбора.

Замер 2026-08-13 подтвердил, что вся остальная цепочка уже работает:

| Проверка | Результат |
|---|---|
| Фильм «Интерстеллар» | 1 «серия», 10 озвучек включая дубляж, видео 360/480/720 в m3u8 и mp4, ссылка получена |
| Сериал «Во все тяжкие» | 63 серии, озвучка, видео, ссылка получена |

В `anicli_api/source/hdrezka.py` для этого уже есть отдельная ветка `is_movie=True`.

## 2. Цель

Один поиск находит аниме, фильмы, сериалы, мультфильмы и шоу. Тип контента виден в выдаче.

## 3. Не-цели

- Не пишем парсеры для других сайтов с кино — это отдельная библиотека и недели работы.
- Не модифицируем установленный `anicli-api`.
- Не добавляем фильмы к аниме-источникам: они по своей природе аниме-только.
- Не меняем воспроизведение, выбор серий и озвучек — оно уже работает для фильмов.

## 4. Пользовательский опыт

```
~ интерстеллар

  1  Интерстеллар [фильм] (hdrezka)
  2  Наука «Интерстеллар» [фильм] (hdrezka)

~ во все тяжкие

  1  Во все тяжкие Завершен (все серии) [сериал] (hdrezka)
  2  Во все тяжкие: Медведи [мультфильм] (hdrezka)
  3  El Camino: Во все тяжкие [фильм] (hdrezka)
```

Бейдж типа показывается **только для не-аниме**. Инструмент аниме-первый, подавляющее
большинство строк — аниме, и бейдж на каждой из них был бы шумом. Фильмы и сериалы,
наоборот, должны выделяться.

## 5. Архитектура

Два новых модуля, оба в существующем плоском пакете:

```
anicli_multi/
  kinds.py         — тип контента: разбор категории из URL, отображаемое имя
  hdrezka_all.py   — экстрактор hdrezka без фильтра категорий
```

### kinds.py

```
ANIME = "аниме"
CATEGORY_TO_KIND = {"animation": "аниме", "films": "фильм", "series": "сериал",
                    "cartoons": "мультфильм", "show": "шоу"}
KNOWN_CATEGORIES  — множество ключей CATEGORY_TO_KIND
CATEGORY_SOURCES  — источники, у которых тип берётся из URL; сейчас {"hdrezka"}

category_from_url(url) -> str   первый сегмент пути, "" если разобрать нечего
resolve_kind(source, url) -> str
```

`resolve_kind` возвращает `ANIME` для любого источника не из `CATEGORY_SOURCES`.
Это осознанно, а не через общий разбор URL: у аниме-источников свои схемы путей
(`/anime/`, `/release/`), и совпадение сегмента с `films` дало бы ложный тип.

### hdrezka_all.py

`UnfilteredPageSearch(PageSearch)` переопределяет `_split_doc`: берёт все элементы
`.b-content__inline_item` с атрибутом `data-url`, без проверки на `/animation/`.

`HdrezkaAllExtractor(hdrezka.Extractor)` принимает `categories` и переопределяет
`search`/`a_search`: разбирает страницу нефильтрованным парсером, затем **отбрасывает
строки по категории уже после разбора**. Фильтрация после разбора, а не внутри
`_split_doc`, выбрана потому, что `_split_doc` вызывается из classmethod-фабрики
`fetch`/`async_fetch`, куда конфигурацию экземпляра не передать.

### Подключение

`build_extractors` получает реестр переопределений:

```
EXTRACTOR_OVERRIDES = {"hdrezka": <фабрика HdrezkaAllExtractor>}
```

Для остальных источников поведение не меняется.

## 6. Правка группировки

**Это обязательная часть, а не улучшение.** Сейчас ключ группы — нормализованное
название. С добавлением фильмов аниме «Тетрадь смерти» с animego и одноимённый игровой
фильм с hdrezka склеились бы в одну строку. Это ровно та «каша», против которой
написана исходная спека (§6).

Ключ группы становится парой **(тип, нормализованное название)**:

- hdrezka `/animation/` «Наруто: Ураганные хроники» → тип `аниме` → склеивается с animego
- hdrezka `/films/` «Тетрадь смерти» → тип `фильм` → остаётся отдельно от аниме

`TitleGroup` получает поле `kind: str`, а тип поля `key` меняется с `str` на
`tuple[str, str]` — пара `(kind, нормализованное название)`. Существующие тесты
группировки, обращающиеся к `key`, обновляются под новый тип.
`group_results` определяет тип через `resolve_kind(source, result.url)`.

Цена: если hdrezka положит полнометражное аниме в `/films/`, оно не склеится с
аниме-источниками. Это разделение вместо ошибочной склейки — то же правило, что принято
в исходной спеке.

## 7. Конфиг

Новое поле:

```json
"hdrezka_categories": ["animation", "films", "series", "cartoons", "show"]
```

По умолчанию — все пять. Прежнее поведение возвращается значением `["animation"]`.
Неизвестные категории отбрасываются при чтении конфига с предупреждением; если после
отбрасывания список пуст, применяется значение по умолчанию.

## 8. Устойчивость

Мы зависим от приватного `PageSearch._split_doc` и CSS-класса `.b-content__inline_item`.

`compat.py` дополнительно проверяет, что `PageSearch` существует, имеет `_split_doc`, и что
из `anicli_api.source.hdrezka` импортируются `Search` и `Extractor`. При расхождении
переопределение **не устанавливается**: `hdrezka` работает штатным экстрактором в
аниме-режиме, пользователь получает предупреждение. Инструмент остаётся рабочим.

Ошибки во время самого поиска уже обрабатываются: `search_all` ловит исключение источника
и показывает его отдельной строкой, не роняя остальные.

## 9. Тесты

Без сети:

- разбор категории из URL: обычный адрес, адрес без пути, мусор, пустая строка;
- `resolve_kind`: hdrezka по категориям, любой другой источник → `аниме`;
- **фильм и аниме с одинаковым названием не склеиваются** — главный тест этой спеки;
- аниме с hdrezka и с animego по-прежнему склеиваются;
- фильтрация по списку категорий, включая пустой и неизвестные значения;
- бейдж показывается для не-аниме и не показывается для аниме;
- чтение конфига с неизвестными и пустыми категориями.

С сетью (маркер `network`):

- «интерстеллар» находит строку с типом `фильм`;
- «во все тяжкие» находит строку с типом `сериал`;
- «наруто» по-прежнему даёт группу с несколькими источниками (регрессия на склейку).

## 10. Риски

| Риск | Митигация |
|---|---|
| Смена вёрстки hdrezka ломает нефильтрованный разбор | Проверка в `compat.py`, откат на штатный экстрактор |
| Кино только с одного источника; hdrezka лёг — кино не найдётся | Задокументировано в README, деградация мягкая |
| Добавление типа в ключ разобьёт группу, которая раньше склеивалась | Осознанный размен в пользу разделения |
| Выдача по общим запросам станет длиннее | Бейджи типов делают её читаемой; сортировка не меняется |
