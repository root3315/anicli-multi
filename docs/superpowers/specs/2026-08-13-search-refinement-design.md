# Фильтрация и чистота выдачи

**Дата:** 2026-08-13
**Статус:** согласован
**Предшествующие спеки:** [anicli-multi](2026-08-13-anicli-multi-design.md), [фильмы и сериалы](2026-08-13-movies-and-series-design.md)

## 1. Проблема

Запрос «жизнь по вызову сериал» вернул 103 строки, среди которых нужного сериала не было
видно вообще. Разбор показал три независимые причины.

**Слово типа в запросе ломает поиск.** Без него сериал — первая строка выдачи. С ним запрос
уходит в источники как есть: hdrezka ищет «жизнь по вызову сериал» и отдаёт 36 мусорных
результатов вместо 4, а релевантность падает до низшего ранга у всех строк, из-за чего
сортировка откатывается к числу источников и наверх всплывает аниме.

**Аниме-источники шумят.** animego вернул 50 результатов на «жизнь по вызову», сопоставляя
отдельные слова. В выдаче 68 аниме против 4 нужных строк.

**Обрезка таблицы обманывает.** `table_fill_limited_rows` из anicli-ru рисует 21 строку,
затем `+79 more`, затем последние 3. Скрытые строки **остаются выбираемыми по номеру**:
можно ввести 45 и попасть в то, чего не было на экране.

## 2. Замер отсечения по релевантности

Сколько строк останется, если оставить только те, где запрос встречается в названии
(2026-08-13):

| Запрос | Всего | После отсечения |
|---|---|---|
| жизнь по вызову | 72 | 4 |
| во все тяжкие | 55 | 4 |
| re zero | 48 | 21 |
| атака титанов | 34 | 29 |
| наруто | 61 | 57 |
| интерстеллар | 3 | 2 |

Ни один запрос не обнулился, но защита от пустой выдачи всё равно нужна.

## 3. Цель

Найти нужное с первой попытки, включая формулировки вида «название + тип».

## 4. Не-цели

- Не вводим отдельный синтаксис фильтров (`--kind сериал`): естественного слова в запросе
  достаточно, а лишний синтаксис надо помнить.
- Не добавляем нечёткое сопоставление названий — оно склеивает разные тайтлы (см. первую спеку §6).
- Не меняем набор источников и воспроизведение.

## 5. Тип в запросе как фильтр

Слово типа в начале или конце запроса вырезается из текста, уходящего в источники, и
становится фильтром по типу контента.

Распознаются: `сериал`, `сериалы`, `сериала`, `фильм`, `фильмы`, `фильма`, `кино`, `аниме`,
`мультфильм`, `мультфильмы`, `мультик`, `мультики`, `мультсериал`, `шоу`.

Условия срабатывания:

- слово стоит **первым или последним** токеном;
- после удаления остаётся хотя бы один токен.

Второе условие означает, что запрос «аниме» ищет тайтл со словом «аниме», а не фильтрует
пустоту.

**Фильтр мягкий.** Если под тип не подошло ничего, показывается вся найденная выдача с
пометкой. Это защищает случаи, где слово типа — часть настоящего названия: «наруто последний
фильм» находит «Наруто 10: Последний фильм», хотя тот лежит в разделе аниме.

## 6. Отсечение нерелевантного

Из выдачи убираются группы, у которых запрос не встречается в нормализованном названии
(ранг релевантности 3). Если после отсечения не осталось ничего, показывается вся выдача:
пустой экран хуже неточного.

Число скрытых сообщается под таблицей.

## 7. Честный лимит вывода

Собственный рендер вместо `render_table` из anicli-ru. Отличия:

- строки не прячутся в середине: показываются первые `max_results` (по умолчанию 30);
- нумерация в таблице соответствует видимым строкам один к одному;
- если строк больше лимита, под таблицей честное «показано 30 из 57 — уточните запрос».

В FSM передаётся **только показанный срез**, поэтому выбрать невидимую строку невозможно
по построению.

## 8. Архитектура

Два новых модуля и правка команды поиска:

```
anicli_multi/
  query.py    — разбор запроса: текст для источников + фильтр по типу
  refine.py   — отсечение нерелевантного, фильтр по типу, срез до лимита
  render.py   — таблица результатов без скрытых строк
```

`query.parse_query(raw) -> ParsedQuery(text, kind, raw)`

`refine.refine(groups, query_key, kind, max_results) -> RefineResult` с полями
`groups` (что показывать), `total` (сколько после отсечения и фильтра), `hidden_irrelevant`,
`kind_filter_dropped`.

`render.render_groups(title, groups)` печатает таблицу.

`commands.multi_search_command` связывает: разбирает запрос, ищет по `parsed.text`,
группирует, прогоняет через `refine`, рендерит, кладёт показанный срез в контекст FSM.

## 9. Конфиг

Новое поле `max_results` (по умолчанию 30). Значение меньше 1 игнорируется.

## 10. Сообщения под таблицей

Порядок: отказы источников, затем одна строка со сводкой, затем подсказка навигации.

Сводка собирается из применимых частей: «показано 30 из 57», «скрыто 68 нерелевантных»,
«ничего с типом «сериал», показываю всё». Если сводки нет, строка не печатается.

## 11. Тесты

Без сети:

- разбор запроса: тип в конце, тип в начале, тип в середине (не срабатывает), тип как
  единственное слово (не срабатывает), запрос без типа, все синонимы, регистр;
- отсечение: нерелевантные убираются; если релевантных нет — возвращается всё;
- фильтр по типу: применяется; при пустом результате мягко откатывается с флагом;
- срез: не длиннее лимита, `total` отражает величину до среза;
- рендер: число строк в таблице равно числу групп, нумерация с 1.

С сетью:

- «жизнь по вызову сериал» — первая строка имеет тип «сериал» и содержит «жизнь по вызову»;
- «наруто» — выдача не пустая и не длиннее лимита.

## 12. Риски

| Риск | Митигация |
|---|---|
| Слово типа — часть настоящего названия | Мягкий откат фильтра, покрыт тестом |
| Отсечение спрячет нужное при опечатке | При пустом результате показывается всё |
| Лимит скроет нужную строку | Честная пометка с призывом уточнить запрос; сортировка по релевантности ставит нужное вверх |
| Свой рендер разойдётся с оформлением anicli-ru | Используется тот же стиль рамки rich (`box.ROUNDED`) |
